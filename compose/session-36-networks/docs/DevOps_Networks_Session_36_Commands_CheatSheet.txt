# sudo ss -lntp | grep ':8086 ' || true

Explanation:
Checks whether TCP port 8086 is already in use. The final shell condition keeps the command sequence successful when grep finds no match.

Options:
- -l = --listening (listening): show only listening sockets.
- -n = --numeric (numeric): show numeric addresses and ports instead of resolving names.
- -t = --tcp (TCP): show TCP sockets.
- -p = --processes (processes): show the process using each socket when permitted.
- | = pipe operator: send the output of ss to grep.
- ':8086 ' = grep search text: match entries containing port 8086 followed by a space.
- || = OR operator: run the command on the right only if the command on the left fails.
- true = shell command that returns a successful exit status.
------------------------------------------------------------

# wget -q -O /dev/null http://127.0.0.1/health || exit 1

Explanation:
Checks the local Nginx health endpoint without saving the response body. If the request fails, the healthcheck exits with status 1.

Options:
- -q = --quiet (quiet): suppress normal wget output.
- -O /dev/null = --output-document=/dev/null (output document): write the downloaded content to /dev/null instead of a file.
- || = OR operator: run exit 1 only if wget fails.
- exit 1 = shell exit command: return exit status 1 to mark the healthcheck as failed.

------------------------------------------------------------
# pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}

Explanation:
Checks whether PostgreSQL is ready to accept connections. The double dollar signs are correct in this Compose healthcheck because Compose must pass the variable references to the container shell.

Options:
- -U $${POSTGRES_USER} = --username=$${POSTGRES_USER} (username): use the PostgreSQL user stored in POSTGRES_USER.
- -d $${POSTGRES_DB} = --dbname=$${POSTGRES_DB} (database name): check the database stored in POSTGRES_DB.
- $$ = Compose dollar-sign escape: pass a literal dollar sign so the container shell can expand the environment variable.

# docker compose exec adminer php -r 'echo "db=", gethostbyname("db"), PHP_EOL; echo "alias=", gethostbyname("postgres-db"), PHP_EOL;'

Explanation:
Technical correction: The lesson also used ping inside the adminer container for DNS troubleshooting, but the Adminer image was not shown to include the ping binary. This existing PHP command from the same lesson is the reliable DNS check and also tests the postgres-db alias.

Options:
- adminer = docker compose exec service argument: run the following command inside the adminer service container.
- -r = PHP CLI run-code option: execute the supplied PHP code directly without script tags.
- gethostbyname("db") = PHP function call: resolve the db service name.
- gethostbyname("postgres-db") = PHP function call: resolve the postgres-db network alias.
------------------------------------------------------------

------------------------------------------------------------
# docker compose exec adminer php -r '$s=@fsockopen("db",5432,$errno,$errstr,3); if ($s) { echo "DB TCP OK\n"; fclose($s); } else { fwrite(STDERR,"DB TCP FAIL: $errstr\n"); exit(1); }'

Explanation:
Tests a real TCP connection from the adminer container to db on port 5432. The connection attempt uses a three-second timeout and exits with status 1 on failure.

Options:
- adminer = docker compose exec service argument: run the following command inside the adminer service container.
- -r = PHP CLI run-code option: execute the supplied PHP code directly without script tags.
- fsockopen("db",5432,...,3) = PHP function call: open a TCP connection to db on port 5432 with a three-second timeout.
- exit(1) = PHP exit call: return status 1 when the TCP connection fails.
------------------------------------------------------------
