# docker info >/dev/null && echo "Docker Engine: OK"

Explanation:
Checks whether the Docker Engine can return system information, discards that output, and prints a success message only if the check succeeds.

Options:
- > = shell output redirection: Send standard output to the specified file or device.
- /dev/null = null device: Discard the redirected standard output.
- && = shell AND operator: Run the next command only if the previous command exits successfully.
------------------------------------------------------------
# sudo ss -lntp | grep ':5433 ' || echo "Port 5433 is free"

Explanation:
Checks listening TCP sockets for port 5433. If no matching socket is found, it prints that the port is free.

Options:
- -l = --listening (listening): Show only listening sockets.
- -n = --numeric (numeric): Show numeric addresses and port numbers instead of resolving names.
- -t = --tcp (TCP): Show TCP sockets.
- -p = --processes (processes): Show the process using each socket when permitted.
- | = shell pipe operator: Send the output of `ss` to `grep`.
- || = shell OR operator: Run the final `echo` command only if the previous pipeline fails or finds no match.

# pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}

Explanation:
Checks whether PostgreSQL is ready to accept connections in the Compose healthcheck. The doubled dollar signs prevent Docker Compose from interpolating the variables before the container shell receives them.

Options:
- -U = username: Use the PostgreSQL user specified by `POSTGRES_USER`.
- -d = database name: Check the PostgreSQL database specified by `POSTGRES_DB`.
- $$ = Compose dollar-sign escape: Pass a literal `$` through Compose so the variable can be expanded inside the container.

# docker compose exec db sh -c 'pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"'

Explanation:
Runs a shell inside the running `db` service and checks whether PostgreSQL is ready using the container's environment variables.

Options:
- -c = shell command string: Tell `sh` to execute the following quoted command string.
- -U = username: Use the PostgreSQL user stored in `POSTGRES_USER`.
- -d = database name: Check the PostgreSQL database stored in `POSTGRES_DB`.

# docker inspect "$(docker compose ps -q db)" --format '{{range .Mounts}}{{println .Type .Name .Source "->" .Destination}}{{end}}'

Explanation:
Finds the container ID for the `db` service and prints each mount type, name, source, and destination using a Go template.

Options:
- -q = --quiet (quiet): In `docker compose ps`, print only container IDs.
- $(...) = command substitution: Run the inner command and substitute its output into the outer `docker inspect` command.
- --format = output format template: Format the inspect output with the supplied Go template.

# docker compose exec db psql -U appuser -d appdb -c "CREATE TABLE IF NOT EXISTS students (id SERIAL PRIMARY KEY, name TEXT NOT NULL);"

Explanation:
Runs `psql` inside the `db` service and creates the `students` table if it does not already exist.

Options:
- -U = --username (username): Connect as PostgreSQL user `appuser`.
- -d = --dbname (database name): Connect to database `appdb`.
- -c = --command (command): Execute the supplied SQL statement and then exit.
------------------------------------------------------------
# docker compose exec db psql -U appuser -d appdb -c "INSERT INTO students (name) VALUES ('student-01');"

Explanation:
Runs `psql` inside the `db` service and inserts one row named `student-01` into the `students` table.

Options:
- -U = --username (username): Connect as PostgreSQL user `appuser`.
- -d = --dbname (database name): Connect to database `appdb`.
- -c = --command (command): Execute the supplied SQL statement and then exit.
------------------------------------------------------------
# docker compose exec db psql -U appuser -d appdb -c "SELECT * FROM students;"

Explanation:
Runs `psql` inside the `db` service and returns all rows from the `students` table.

Options:
- -U = --username (username): Connect as PostgreSQL user `appuser`.
- -d = --dbname (database name): Connect to database `appdb`.
- -c = --command (command): Execute the supplied SQL statement and then exit.
