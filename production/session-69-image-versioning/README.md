# Session 69 — Docker Image Versioning

A practical Docker Production lab for immutable image versioning, Semantic Versioning, Git commit tags, Nexus push/pull, deployment, traceability, and rollback.

## Goal

Create one application release with more than one useful identifier:

- Semantic Version tag, for example `1.0.0`
- Git commit tag, for example `git-a1b2c3d4e5f6`
- Registry digest, generated by the registry after push

Do not reuse an existing release tag for different image content.

## 1. Build a local version

```bash
docker build --build-arg APP_VERSION=1.0.0 -t version-demo:1.0.0 .
docker images version-demo
```

Run it locally:

```bash
docker rm -f version-demo 2>/dev/null || true
docker run -d --name version-demo -p 8080:80 version-demo:1.0.0
curl -fsS http://127.0.0.1:8080/version.txt
```

Expected response:

```text
VERSION=1.0.0
```

## 2. Publish an immutable release to Nexus

The release script publishes two tags that point to the same build:

```text
192.168.94.90:8085/devops/versioning-demo:1.0.0
192.168.94.90:8085/devops/versioning-demo:git-<12-char-sha>
```

Make the script executable once:

```bash
chmod +x release.sh
```

Publish version `1.0.0`:

```bash
./release.sh 1.0.0
```

Publish a later release with a new version instead of overwriting the previous tag:

```bash
./release.sh 1.1.0
```

## 3. Deploy an exact version on DEV-2

Copy the example environment file:

```bash
cd deploy
cp .env.example .env
```

Set `IMAGE_REF` in `.env` to the exact version you want to deploy, then run:

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

Verify the running image reference:

```bash
docker inspect --format='{{.Config.Image}}' versioning-web
```

Verify the version baked into the image:

```bash
curl -fsS http://127.0.0.1:8080/version.txt
```

## 4. Upgrade to a new version

Change only `IMAGE_REF` in `.env`, for example:

```text
IMAGE_REF=192.168.94.90:8085/devops/versioning-demo:1.1.0
```

Then deploy the new immutable tag:

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

## 5. Roll back

Set `IMAGE_REF` back to the previous known-good version:

```text
IMAGE_REF=192.168.94.90:8085/devops/versioning-demo:1.0.0
```

Then pull and recreate the service:

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

Verify again:

```bash
docker inspect --format='{{.Config.Image}}' versioning-web
curl -fsS http://127.0.0.1:8080/version.txt
```

## Practical production rule

Use exact immutable tags or digests for deployment. A moving alias such as `latest`, `stable`, or `production` can exist for convenience, but it should not be the only identifier used to reproduce or roll back a production deployment.
