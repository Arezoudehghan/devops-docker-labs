# docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=<strong-password> \
  -v postgres_data:/var/lib/postgresql/data \
  postgres

Explanation:
Technical correction: The original lesson command did not provide the PostgreSQL initialization password required by the standard PostgreSQL image, so POSTGRES_PASSWORD was added. The command starts a PostgreSQL container and stores its database files in the named volume postgres_data.

Options:
- -d = --detach (detach): Runs the container in the background.
- --name postgres = container name: Assigns the name postgres to the container.
- -e = --env (environment): Sets an environment variable inside the container; here it sets POSTGRES_PASSWORD.
- -v = --volume (volume): Mounts postgres_data at /var/lib/postgresql/data inside the container.
- <strong-password> = placeholder value: Replace this placeholder with the real PostgreSQL password before running the command.

# docker run --rm \
  -v app_data:/data:ro \
  -v /backup/docker:/backup \
  alpine \
  sh -c 'tar czf /backup/app_data_$(date +%F_%H%M).tar.gz -C /data .'

Explanation:
Runs a temporary Alpine container that creates a compressed backup of the app_data volume in /backup/docker. The source volume is mounted read-only and the temporary container is removed when the command finishes.

Options:
- --rm = remove automatically: Automatically removes the temporary container when it exits.
- -v = --volume (volume): Mounts a Docker volume or host path inside the container.
- app_data:/data:ro = volume mapping: Mounts app_data at /data in read-only mode; ro means read-only.
- /backup/docker:/backup = bind mount mapping: Mounts the host directory /backup/docker at /backup inside the container.
- sh -c = command string: Runs the quoted shell command through sh; -c tells the shell to execute the following string.
- tar -c = --create (create): Creates a new archive.
- tar -z = --gzip (gzip): Compresses the archive with gzip.
- tar -f = --file (file): Uses the next value as the archive file name.
- tar -C = --directory (directory): Changes to /data before archiving ..
- $(...) = command substitution: Runs the command inside the parentheses and inserts its output into the file name.
- date +%F_%H%M = date format: %F produces YYYY-MM-DD, %H the hour, and %M the minute.

# services:

  db:
    image: postgres:17
    environment:
      POSTGRES_DB: appdb
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: <strong-password>
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
    name: postgres_data

Explanation:
Technical correction: The original Compose example did not define POSTGRES_PASSWORD, and its later raw docker run -v postgres_data:... backup command could target a different volume because Compose normally prefixes volume names. POSTGRES_PASSWORD and name: postgres_data were added so the PostgreSQL service can initialize correctly and the later backup commands refer to the same named volume.

# docker compose exec -T db \
  pg_dump -U appuser -Fc appdb \
  > /backup/postgres/appdb_$(date +%F_%H%M).dump

Explanation:
Runs pg_dump inside the Compose service db and writes a custom-format logical backup of appdb to the host backup directory. The host shell performs the output redirection.

Options:
- -T = --no-TTY (no TTY): Disables pseudo-TTY allocation for docker compose exec.
- pg_dump -U = --username (username): Connects as PostgreSQL user appuser.
- pg_dump -F = --format (format): Selects the output format.
- c in -Fc = custom format: Uses PostgreSQL custom archive format.
- > = output redirection: Writes standard output to the specified dump file and replaces that file if it already exists.
- $(...) = command substitution: Inserts the output of the inner date command into the backup file name.
- date +%F_%H%M = date format: %F produces YYYY-MM-DD, %H the hour, and %M the minute.
------------------------------------------------------------

------------------------------------------------------------
# docker compose exec -T db \
  pg_restore \
  -U appuser \
  -d appdb \
  --clean \
  --if-exists \
  < /backup/postgres/appdb_2026-08-19_0200.dump

Explanation:
Runs pg_restore inside the Compose service db and restores the specified custom-format dump into appdb. Existing database objects are cleaned before recreation when they exist.

Options:
- -T = --no-TTY (no TTY): Disables pseudo-TTY allocation for docker compose exec.
- -U = --username (username): Connects as PostgreSQL user appuser.
- -d = --dbname (database name): Restores into the database appdb.
- --clean = clean: Drops database objects before recreating them from the archive.
- --if-exists = if exists: Adds existence checks when dropping objects, reducing errors for objects that are already absent.
- < = input redirection: Sends the contents of the dump file to the standard input of pg_restore.
