# sudo ss -lntp | grep ':8085'

Explanation:
Shows listening TCP sockets and filters the result to entries containing port 8085.

Options:
- -l = --listening: Show only listening sockets.
- -n = --numeric: Show numeric addresses and port numbers instead of resolving names.
- -t = --tcp: Show TCP sockets.
- -p = --processes: Show the process using each socket.
- | = shell pipe operator: Send the output of ss to grep.

# docker login 192.168.94.90:8085 -u "$NEXUS_USER"

Explanation:
Technical correction: The lesson used the placeholder <NEXUS_USER>, which is not directly executable in Bash because angle brackets are shell redirection syntax. This corrected form uses the NEXUS_USER shell variable as the Nexus username.

Options:
- -u = --username: Specify the registry username.
- "$NEXUS_USER" = shell variable value: Use the value stored in the NEXUS_USER environment variable as the username.

# printf '%s' "$NEXUS_PASSWORD" | docker login 192.168.94.90:8085 -u "$NEXUS_USER" --password-stdin

Explanation:
Technical correction: The lesson also showed docker login --password-stdin alone as an incomplete syntax example; this complete command supplies the username, registry, and password input. It prints the Nexus password and pipes it to Docker login through standard input.

Options:
- %s = printf string format: Print the supplied value as a string.
- "$NEXUS_PASSWORD" = shell variable value: Use the value stored in NEXUS_PASSWORD.
- | = shell pipe operator: Send the output of printf to docker login.
- -u = --username: Specify the registry username.
- "$NEXUS_USER" = shell variable value: Use the value stored in NEXUS_USER as the username.
- --password-stdin = read password from standard input: Read the registry password from stdin instead of the command line.
