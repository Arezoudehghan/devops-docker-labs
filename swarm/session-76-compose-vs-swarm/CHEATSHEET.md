# Session 76 — Docker Compose vs Docker Swarm Cheat Sheet

A command-focused reference for **Session 76 only**.  
The commands below are taken from this lab and grouped by purpose.

> Replace documentation-only example addresses such as `192.0.2.10` and `192.0.2.11` with the actual addresses assigned to your own lab VMs.

## 1. Environment and Swarm status checks

```bash
docker --version
```

Shows the installed Docker Engine version.

```bash
docker compose version
```

Shows the installed Docker Compose plugin version.

```bash
docker info --format 'Swarm={{.Swarm.LocalNodeState}}'
```

Shows whether the local Docker Engine is currently in Swarm mode.

```bash
docker info --format 'Swarm={{.Swarm.LocalNodeState}} ControlAvailable={{.Swarm.ControlAvailable}}'
```

Shows Swarm status and whether the current node has manager control-plane capability.

```bash
hostname
```

Displays the current host name.

```bash
ip -br addr
```

Displays network interfaces and IP addresses in a compact format.

## 2. Image checks

```bash
docker image inspect nginx:alpine
```

Checks whether the `nginx:alpine` image exists locally and displays its metadata.

```bash
docker pull nginx:alpine
```

Pulls the Nginx Alpine image from the configured registry.

```bash
docker image ls nginx
```

Lists local Nginx images.

## 3. Docker Compose lab

```bash
cd swarm/session-76-compose-vs-swarm/compose
```

Moves into the Compose lab directory.

```bash
docker compose config
```

Renders and validates the resolved Compose configuration.

```bash
docker compose config --quiet
```

Validates the Compose file without printing the rendered configuration.

```bash
docker compose up -d
```

Starts the Compose application in detached mode.

```bash
docker compose ps
```

Shows containers belonging to the current Compose project.

```bash
docker ps
```

Shows running containers on the current Docker host.

```bash
curl http://127.0.0.1:8088
```

Tests the Compose application through the local published port.

```bash
curl http://192.0.2.11:8088
```

Tests the Compose application through the example address of `DEV-2`.

```bash
docker inspect --format '{{json .State.Health}}' session76-compose-web-1
```

Displays the container health-check state. Use the actual container name if it differs.

```bash
docker compose down
```

Stops and removes the Compose project resources created by this lab.

## 4. Swarm initialization and node membership

```bash
docker swarm init --advertise-addr 192.0.2.10
```

Initializes Swarm mode on the manager and advertises the manager address to other nodes.

```bash
docker swarm join-token worker
```

Displays the worker join command and worker join token.

```bash
docker swarm join --token SWMTKN-xxxxxxxxxxxxxxxx 192.0.2.10:2377
```

Example worker join command. Always use the real command generated by your own manager and never commit the real token.

```bash
docker node ls
```

Lists Swarm nodes, roles, availability, and manager status. Run from a manager node.

## 5. Swarm networking checks

```bash
docker network ls
```

Lists Docker networks, including Swarm-related networks such as `ingress`.

```bash
ss -lntup | grep -E '2377|7946|4789'
```

Checks local listening sockets related to Swarm management, node communication, and overlay networking.

## 6. Swarm stack deployment

```bash
cd swarm/session-76-compose-vs-swarm/swarm
```

Moves into the Swarm stack directory.

```bash
docker stack config -c stack.yaml
```

Renders and validates the Swarm stack configuration.

```bash
docker stack config -c stack.yaml > /dev/null
```

Validates the stack file without printing the rendered output.

```bash
docker stack deploy -c stack.yaml compare
```

Deploys the stack with the stack name `compare`.

```bash
docker stack ls
```

Lists deployed stacks.

```bash
docker stack services compare
```

Lists services in the `compare` stack and shows replica status.

```bash
docker service ps compare_web
```

Shows the tasks created for the `compare_web` service and the nodes where they are scheduled.

```bash
docker stack ps compare
```

Shows tasks belonging to the entire `compare` stack.

## 7. Routing Mesh tests

```bash
curl http://192.0.2.10:8088
```

Tests the published service port through the example manager address.

```bash
curl http://192.0.2.11:8088
```

Tests the same published service through the example worker address.

```bash
for i in {1..10}; do curl -s http://192.0.2.10:8088; echo; done
```

Sends repeated requests to observe responses from different Swarm tasks.

## 8. Desired state and reconciliation

```bash
docker ps --filter label=com.docker.swarm.service.name=compare_web
```

Lists local containers that belong to the `compare_web` Swarm service.

```bash
docker rm -f CONTAINER_ID
```

Forcibly removes one task container for the lab so Swarm reconciliation can recreate the desired replica.

```bash
docker service ps compare_web
```

Verifies the service task history after a task container is removed.

```bash
docker stack services compare
```

Checks whether the service returns to its desired replica count.

## 9. Swarm service scaling

```bash
docker service scale compare_web=5
```

Changes the desired replica count to five.

```bash
docker service ps compare_web
```

Shows the new tasks created during scaling.

```bash
docker service scale compare_web=3
```

Returns the desired replica count to three.

```bash
docker service ls
```

Lists Swarm services and their current replica status.

## 10. Node drain and reactivation

```bash
docker node update --availability drain dev-2
```

Places `dev-2` in drain mode so Swarm stops scheduling tasks there and reschedules existing service tasks elsewhere.

```bash
docker node ls
```

Verifies the node availability state.

```bash
docker service ps compare_web
```

Shows where the affected service tasks are rescheduled.

```bash
docker node update --availability active dev-2
```

Returns `dev-2` to active scheduling availability.

## 11. Troubleshooting

```bash
docker service ps compare_web --no-trunc
```

Shows full task IDs and complete task error messages.

```bash
docker service inspect compare_web --pretty
```

Displays a readable summary of the Swarm service specification.

```bash
docker info
```

Displays detailed Docker Engine and Swarm information.

```bash
docker ps -a
```

Shows running and stopped containers on the current node.

```bash
docker inspect --format '{{json .State.Health}}' CONTAINER_ID
```

Displays health-check details for a specific container.

```bash
docker network ls
```

Checks available local and Swarm networks.

## 12. Cleanup

```bash
docker stack rm compare
```

Removes the `compare` stack while leaving the Swarm cluster enabled.

```bash
docker stack ls
```

Verifies that the stack has been removed.

## Quick interview reminders

- `docker compose up` deploys to the current Docker Engine; it does not schedule workloads across Swarm nodes.
- A Swarm **service** defines desired state.
- A Swarm **task** is one scheduled unit of work for a service.
- A task normally results in a container running on a node.
- Swarm reconciliation tries to make actual state match desired state.
- `mode: ingress` enables the Swarm routing mesh for a published service port.
- `drain` prevents new task scheduling on a node and causes Swarm service tasks to be moved away.
- A single-manager Swarm is useful for labs but does not provide manager high availability.
