# docker run --rm ubuntu:24.04 id

Explanation:
Runs an Ubuntu 24.04 container, executes `id` inside it, and removes the container automatically when it exits.

Options:
- --rm = automatically remove the container when it exits.
------------------------------------------------------------
# docker run --rm --privileged ubuntu:24.04 id

Explanation:
Runs an Ubuntu 24.04 container in privileged mode and executes `id` inside it.

Options:
- --rm = automatically remove the container when it exits.
- --privileged = give the container extended privileges and broad device access.

# docker run --rm \
  --privileged \
  ubuntu:24.04 \
  sh -c 'ip link add dummy0 type dummy && ip link show dummy0'

Explanation:
Runs a privileged container, creates the `dummy0` interface, and then displays it.

Options:
- --rm = automatically remove the container when it exits.
- --privileged = give the container extended privileges and broad device access.
- -c = command string for `sh`: execute the following quoted string as shell commands.
- && = shell AND operator: run the second command only if the first command succeeds.
------------------------------------------------------------
# docker run --rm \
  --cap-add=NET_ADMIN \
  ubuntu:24.04 \
  sh -c 'ip link add dummy0 type dummy && ip link show dummy0'

Explanation:
Runs a container with only the `NET_ADMIN` capability added, then creates and displays the `dummy0` interface.

Options:
- --rm = automatically remove the container when it exits.
- --cap-add=NET_ADMIN = add the `NET_ADMIN` Linux capability to the container.
- -c = command string for `sh`: execute the following quoted string as shell commands.
- && = shell AND operator: run the second command only if the first command succeeds.
------------------------------------------------------------
# docker run --rm \
  --cap-drop=CHOWN \
  ubuntu:24.04 \
  sh -c 'touch /tmp/test && chown 1000:1000 /tmp/test'

Explanation:
Runs a container with the `CHOWN` capability removed, creates `/tmp/test`, and then attempts to change its owner.

Options:
- --rm = automatically remove the container when it exits.
- --cap-drop=CHOWN = remove the `CHOWN` Linux capability from the container.
- -c = command string for `sh`: execute the following quoted string as shell commands.
- && = shell AND operator: run the second command only if the first command succeeds.
- 1000:1000 = target numeric UID and GID used by `chown`.
------------------------------------------------------------
# docker run --rm \
  --cap-drop=ALL \
  ubuntu:24.04 \
  sh -c 'touch /tmp/test && chown 1000:1000 /tmp/test'

Explanation:
Runs a container with all Linux capabilities removed, creates `/tmp/test`, and then attempts to change its owner.

Options:
- --rm = automatically remove the container when it exits.
- --cap-drop=ALL = remove all Linux capabilities from the container.
- -c = command string for `sh`: execute the following quoted string as shell commands.
- && = shell AND operator: run the second command only if the first command succeeds.
- 1000:1000 = target numeric UID and GID used by `chown`.
------------------------------------------------------------
# docker run --rm \
  --cap-drop=ALL \
  --cap-add=CHOWN \
  ubuntu:24.04 \
  sh -c 'touch /tmp/test && chown 1000:1000 /tmp/test && ls -ln /tmp/test'

Explanation:
Runs a container with all capabilities removed except `CHOWN`, then creates the file, changes its owner, and lists it using numeric IDs.

Options:
- --rm = automatically remove the container when it exits.
- --cap-drop=ALL = remove all Linux capabilities from the container.
- --cap-add=CHOWN = add the `CHOWN` Linux capability back to the container.
- -c = command string for `sh`: execute the following quoted string as shell commands.
- && = shell AND operator: run the next command only if the previous command succeeds.
- 1000:1000 = target numeric UID and GID used by `chown`.
- -l = long listing format for `ls`.
- -n = --numeric-uid-gid: show numeric user and group IDs instead of names.
------------------------------------------------------------

# docker run --rm \
  --security-opt no-new-privileges=true \
  ubuntu:24.04 \
  sh -c 'grep NoNewPrivs /proc/1/status'

Explanation:
Runs a temporary Ubuntu container with `no-new-privileges` enabled and checks the kernel status field for PID 1.

Options:
- --rm = automatically remove the container when it exits.
- --security-opt no-new-privileges=true = set the container security option that prevents processes from gaining new privileges.
- -c = command string for `sh`: execute the following quoted string as a shell command.
------------------------------------------------------------
# docker run -d \
  --name session55-secure \
  --cap-drop=ALL \
  --cap-add=CHOWN \
  --security-opt no-new-privileges=true \
  ubuntu:24.04 \
  sleep infinity

Explanation:
Starts a long-running detached container named `session55-secure` with all capabilities removed except `CHOWN` and with privilege escalation blocked.

Options:
- -d = --detach (detach): run the container in the background.
- --name session55-secure = assign the container name `session55-secure`.
- --cap-drop=ALL = remove all Linux capabilities from the container.
- --cap-add=CHOWN = add only the `CHOWN` Linux capability.
- --security-opt no-new-privileges=true = prevent processes from gaining new privileges.
------------------------------------------------------------

# docker rm -f session55-secure 2>/dev/null || true

Explanation:
Force-removes `session55-secure`, hides any error message, and makes the overall shell command succeed even if the removal fails.

Options:
- -f = --force (force): force removal of the running container by sending it a termination signal first.
- 2>/dev/null = redirect file descriptor 2, standard error, to `/dev/null`.
- || = shell OR operator: run `true` only if `docker rm` fails.
